# T3 — Publish on GitHub Release

## What to do

Change `publish.yml` triggers to `release: published` and `workflow_call`
(input `version`). Remove the `repository_dispatch` trigger; T4 owns it.

## Context

The current `publish.yml` takes `workflow_dispatch` and `repository_dispatch`.
The version comes from `github.event.release.tag_name` or the `workflow_call`
input. Keep `workflow_dispatch` for manual recovery.

## Implementation

1. Triggers: `release: [published]`, `workflow_call: inputs.version`, `workflow_dispatch: inputs.version`.
2. `VERSION` resolves from the input or the release tag; validate `X.Y.Z`.
3. Keep assemble, smoke, and ordered publish with skip-if-exists.
4. Update the README release section.

## Done when

- [ ] `actionlint` (or YAML parse) passes.
- [ ] A published release `X.Y.Z` runs the job with `VERSION=X.Y.Z` (observed in T6).
