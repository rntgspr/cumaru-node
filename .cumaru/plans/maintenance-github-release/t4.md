# T4 — Sync workflow for upstream dispatch

## What to do

Add `.github/workflows/sync.yml` for `repository_dispatch` type
`cumaru-release`. It creates the release in this repository and calls
`publish.yml`.

## Context

A release created with `GITHUB_TOKEN` does not trigger `release: published`,
so the publish runs through `workflow_call` in the same run. The job needs
`contents: write` and `id-token: write` (inherited by the called workflow).

## Implementation

1. Read and validate `client_payload.version` as `X.Y.Z`.
2. Confirm the upstream release exists: `gh release view "$VERSION" -R rntgspr/cumaru`.
3. If `gh release view "$VERSION"` succeeds here, stop with success.
4. `gh release create "$VERSION" --target main --title "Cumaru $VERSION" --notes "Wraps https://github.com/rntgspr/cumaru/releases/tag/$VERSION"`.
5. Second job: `uses: ./.github/workflows/publish.yml` with `version`, `secrets: inherit`.

## Done when

- [ ] `gh api repos/rntgspr/cumaru-node/dispatches -f event_type=cumaru-release -F client_payload[version]=0.15.1` creates release `0.15.1` and runs publish.
- [ ] A second identical dispatch exits successfully without a new release.
