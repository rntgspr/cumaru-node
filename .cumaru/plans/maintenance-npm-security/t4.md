# T4 — CI guard for npm v12 install defaults

## What to do

Make CI prove that the wrapper installs and runs under npm v12 defaults, and fail if an install
script ever appears.

## Context

npm v12 sets `allowScripts` off, so packages that build or download binaries in install scripts
break. This wrapper relies only on `optionalDependencies` tarballs. CI today uses the npm that
ships with Node 24.

## Implementation

1. In `ci.yml`, add `npm install --global npm@12` before the install step and print `npm --version`.
2. Add a guard step: for each `npm/*/package.json`, fail if `scripts` has `preinstall`,
   `install`, `postinstall`, or `prepare`; fail if any package contains `binding.gyp`.
3. Keep the existing install and run checks; they now run under npm v12 defaults.
4. README: state that the package has no install scripts and needs no `npm approve-scripts`.

## Done when

- [ ] CI on `main` is green with npm `12.x` printed in the log.
- [ ] A temporary `postinstall` in an assembled manifest makes the guard fail (checked once on a branch).
