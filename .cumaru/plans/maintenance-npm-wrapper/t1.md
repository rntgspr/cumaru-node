# T1 — Node launcher and main package manifest

## What to do

Create `bin/cumaru.js` and make `package.json` the main `@cumaru/cumaru`
manifest with `bin` and `optionalDependencies` on the four platform packages.

## Context

Platform map, from the upstream release targets:

| Host (`process.platform`/`process.arch`) | Package | Binary asset |
|---|---|---|
| `darwin`/`arm64` | `@cumaru/cli-darwin-arm64` | `cumaru-aarch64-apple-darwin` |
| `darwin`/`x64` | `@cumaru/cli-darwin-x64` | `cumaru-x86_64-apple-darwin` |
| `linux`/`arm64` | `@cumaru/cli-linux-arm64` | `cumaru-aarch64-unknown-linux-musl` |
| `linux`/`x64` | `@cumaru/cli-linux-x64` | `cumaru-x86_64-unknown-linux-musl` |

Linux binaries are static musl builds (upstream checks for no `INTERP`), so
the Linux packages declare `os` and `cpu` only, without `libc`.

## Implementation

1. `bin/cumaru.js`: resolve `<pkg>/cumaru` with `require.resolve`, allow a
   `CUMARU_BINARY` override, run it with `spawnSync` and `stdio: "inherit"`,
   forward the exit code or signal.
2. `package.json`: `bin`, `files`, `engines`, `optionalDependencies`.

## Done when

- [ ] `node bin/cumaru.js --version` prints the binary version when `CUMARU_BINARY` points at a local binary.
- [ ] An unsupported host prints an error and exits non-zero.
